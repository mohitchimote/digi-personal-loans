# Build notes — masters, forms, letters and the second deployment (2026-11-13)

What was built on the `dev` branch on this date and where it lives. Kept apart from the older
documents on purpose. The to-do list is in `PENDING_WORK.md`. The Worker is the dev and reference
build; the Java services are production and get parity later.

## 1. Admin area

Navigation is a left rail grouped by purpose, with a landing page, both rendered from one list
(`frontend/src/app/pages/admin/shell/admin-nav.ts`). The rail collapses sideways.

## 2. Masters

Define once, reuse everywhere: Country, State, City, Nationality, Branch, Bank, Bank branch, Industry
sector, Relationship, Loan purposes and more.

- Tables `master_types` (type, parent type, attribute definitions) and `master_items` (code unique per type,
  English and Hebrew name, parent, attributes, active).
- **Codes are generated by the server** from the English name (upper snake case, at most 30 characters, cut at a
  word boundary, `_2` on a clash). People never type a code. City codes come from the source dataset ids.
- Public pick-list `GET /api/masters/:type?parent=&q=&limit=` and bulk `?types=`; admin CRUD under
  `/api/auth/admin/masters` (paged).
- **System lists** are not master rows: `staff` comes from the Users table (staff roles, enabled, in the org
  units linked to the chosen Branch).
- Reference data (all ISO countries, true demonyms, states and cities, Bank of Israel branches) is generated by
  `worker/scripts/seed-reference.ts`. For a remote database with a daily write limit use
  `node scripts/seed-reference-stage.mjs <country codes>` to load cities for chosen countries only.
- Organisation units pick their level and branch from masters.

## 3. Forms use masters; screens use forms

Rule: a screen never names a master. Chain: **screen → form definition → master**.

- A field in a form definition may carry `optionsSource { master, dependsOn?, valueAttribute? }`
  (`worker/src/lib/form-schema-types.ts`). `dependsOn` makes a cascade (Country → State → City).
- The server checks the sources when a draft is saved or published, and checks every submitted value
  (`lib/master-options.ts`). A value already saved is never blocked. A cascade whose parent has nothing under it
  (a country without states) accepts free text.
- `lib/form-master-sources.ts` holds the known pairings and
  `POST /api/auth/admin/form-builder/forms/:formKey/apply-master-sources` publishes a new version with them,
  without overriding anything an admin configured. It also reorders the address fields so parents come first.
- Frontend: `FormFieldOptionsService.options(fieldDef, parentValue)`, the `fieldLabel` pipe for showing a stored
  value, and the shared `app-field-select` component (cascade clearing, old text mapped to codes, free-text
  fallback). Used for personal details (current and previous addresses), company details and both guarantor screens.
- Stored values are codes, so the review, view and case screens show names through `fieldLabel`.
- Old applications keep working: saved text such as "Israel" is mapped to the code on load, and a new `state` field
  is asked for.

## 4. Calculated values

`worker/src/lib/calculated.ts`. Monthly repayment, total payable, total interest and cost per ₪1 are worked
out by the backend and stored in `loan_applications.calculated_json`, in the same write as any change to the loan,
product or approval (`lib/workflow/host.ts`). Letters and screens only read them. A value whose inputs are not
there is left out, never guessed.

## 5. Letters

Spec first: `letter-spec/README.md` is the language-neutral contract, with shared conformance vectors in
`letter-spec/vectors/` (formats, rules, resolve, validate, markup). Both engines must pass them; only the PDF
drawing differs.

| Piece | Where |
|---|---|
| Document model, rules, formats, resolve | `worker/src/lib/letters/{types,rules,formats,resolve}.ts` |
| Rich text (`<b> <i> <u>`, entities) | `lib/letters/markup.ts`; spec section "Rich text" |
| Validator (errors block publishing) | `lib/letters/validate.ts` |
| Live data dictionary and application data | `lib/letters/{dictionary,data}.ts` |
| Storage, render, issue | `lib/letters/service.ts`; tables `letter_templates`, `letter_versions`, `letter_saved_rules`, `letter_images`, `letters_issued` |
| PDF (English then Hebrew, one file) | `lib/pdf/{bilingual,letter-renderer,letter-fonts}.ts`, fonts in `src/assets/fonts` |
| Admin API | `/api/auth/admin/letters` (`routes/admin-letters.ts`) |
| Staff API | `/api/letters` (`routes/letters.ts`), entitlement `letters.issue` |
| Editor | `/admin/letters`, `frontend/src/app/pages/admin/letters/` |

Behaviour worth knowing:
- Templates are versioned: one DRAFT, one PUBLISHED, older ones ARCHIVED. Publishing refuses on validator errors.
- Issuing refuses if the template has errors or the application lacks a value the letter prints. It stores the
  PDF in R2, the template version, the data used and which conditional parts were shown.
- Pictures are PNG or JPEG, at most 500 KB, kept in the database.
- Values filled into text are escaped, so data can never add formatting.
- Hebrew PDF: lines are drawn as single-script runs because the font library chooses one direction per string;
  brackets are mirrored by us. Italic is a synthetic slant (the font has none).
- The editor is a white page (Letter view and Structure view) with a Blocks form view as a third option. The
  frontend holds a copy of the format and rule engine, only to show sample values.
- **Angular 22:** components without an explicit change-detection setting are OnPush. The letter editor edits the
  document in place, so its components set `ChangeDetectionStrategy.Default`, and a converted block gets a fresh id.

- Its secrets are set on that Worker only (`JWT_SECRET`; `RESEND_API_KEY` is not set, so email does not send).
- It was seeded with users, forms, masters, organisation structure and Israel's reference data, then
  apply-master-sources was run on both forms.
- The Admin's login ID was changed directly in both deployed databases (not recorded here); `seed.sql` still has the original, so a reseed would restore it.
- `…loans2` is public, and demo mode shows the login code on screen.
- Migrations: `0019` (letters tables) and `0020` (`calculated_json`) are applied on `digibank2` and locally.

## 7. Running locally

`worker`: `npx wrangler dev` (port 8787). `frontend`: `npx ng serve` (4200, proxies `/api` to the Worker through
`proxy.conf.json`). Tests: `npx vitest run` in `worker` (376 at the time of writing).
